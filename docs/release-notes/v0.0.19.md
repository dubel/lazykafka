# lazykafka v0.0.19

A stability release: a faster Cluster State view, a UI that stays responsive when
the broker is slow, and safer handling of topics and config files.

## Highlights

- **Cluster State opens instantly while you consume.** With a topic being consumed,
  the Cluster State view (`d`) could take 20-40 seconds to load. It now loads in
  milliseconds: offsets are fetched in one batched request per broker, and the
  consumer uses its own connections so it no longer delays other requests.
- **Deleting a topic asks for confirmation.** `r` in the Topics panel now opens a
  confirmation dialog (`Enter` to delete, `Esc` to cancel), like removing a consumer group.

## Fixes

- The UI no longer freezes when the broker stops responding. Previously, a topic refresh
  hanging on an unresponsive broker combined with a reconnect could block every key press
  until the network timed out (10-30+ seconds).
- Sending a message (`Alt+Enter` / `Ctrl+S`) no longer freezes the UI while the
  broker responds; the footer shows "Sending..." until it is done.
- Messages containing `[...]` (for example `[red]` or JSON arrays like `["a"]`) are shown
  exactly as stored instead of being interpreted as colors or cut off. The same applies
  to broker addresses, aliases, consumer group names and config values.
- Pressing `Esc` while Cluster State is loading cancels it; a late result no longer
  pops up over whatever you are doing. Loading gives up after 15 seconds with an error.
- Switching topics quickly no longer leaks background consumers, and messages from the
  previous topic no longer appear after switching.
- Replaying a large topic from the beginning stays smooth: messages are drawn in batches
  and the consume view keeps the last 2,000 messages.
- A single failed health check no longer drops the connection; lazykafka reports the
  connection as lost after 3 consecutive failures (about 15 seconds).
- Fixed data races in the consume panel and connection handling.

## Config and privacy

- `brokers.json` and `settings.json` are written atomically and with permissions `0600`.
- A config file that cannot be read is moved aside to `<name>.corrupt-<timestamp>` instead
  of being replaced by an empty one, so your saved brokers can be recovered.
- Errors while saving brokers are now shown in the Brokers panel footer.
- The application log no longer contains message contents (only topic and size).

## Upgrading

No action needed. Existing `~/.lazykafka` files are read as before; their permissions
are tightened to `0600` the next time they are saved.
